My Hacking Methodology

A systematic, phase-driven approach to ethical hacking — from passive recon to post-exploitation and final report.

01

Reconnaissance

PASSIVE · OSINT · FOOTPRINTING

Recon is the most critical phase. The more I know about the target before touching it, the more precise and efficient the rest of the engagement becomes. All recon at this stage is passive — no packets sent to the target.

I build a complete picture: infrastructure, technology stack, people, exposed assets, and historical data.

Domain & Subdomain EnumCertificate transparency logs (crt.sh), subfinder, amass, and passive DNS to discover all attack surface subdomains.
Shodan / Censys ReconFind exposed services, open ports, and misconfigured assets tied to the target's IP ranges and ASN.
People & OSINTLinkedIn, GitHub, HaveIBeenPwned — identify employees, leaked credentials, and exposed source code.
Tech FingerprintingWappalyzer, BuiltWith, HTTP headers, and error pages to identify frameworks, CMS, server software, and CDNs.

02

Scanning

PORT SCAN · SERVICE DETECTION · VULN SCAN

With a full asset list in hand I move to active scanning — identifying every open port, running service, and software version across all in-scope hosts.

Full-Port Nmap ScanTCP SYN scan on all 65,535 ports. Follow up with service/version detection (-sV) and default scripts (-sC) on discovered ports.
Web Service Discoveryhttpx to probe all discovered hosts for live web services, titles, status codes, and technologies.
Automated Vuln ScanningNuclei templates for CVE detection, misconfigurations, and exposed panels. Used as a supplement to manual work — never a replacement.

Tools

NmaphttpxNucleiMasscan
03

Enumeration

SMB · FTP · SSH · WEB · AD

Deep-dive into each discovered service. The goal is to pull as much information as possible from each service before attempting exploitation — valid usernames, shares, version-specific weaknesses, and misconfigurations.

SMB / Samba EnumList shares, check null sessions, enumerate users and groups via enum4linux-ng and smbclient.
Active Directory ReconBloodHound / SharpHound for AD graph mapping — identify attack paths, Kerberoastable accounts, and AS-REP roasting targets.
Web EnumerationFFUF for directories and virtual hosts. Gobuster for file extensions. Collect all endpoints from JS bundles and Wayback Machine.
Database & SNMPCheck for unauthenticated DB access, SNMP community strings, and anonymous LDAP binds.

Tools

enum4linux-ngsmbclientBloodHound FFUFGobusterldapsearch
04

Exploitation

INITIAL ACCESS · SHELLS · CVE EXPLOITATION

Using the intelligence gathered, I select the most reliable attack path for initial access. Manual exploitation always comes first — I use Metasploit only as a last resort or to confirm a finding.

Public Exploit ResearchSearch ExploitDB, GitHub, and CVE databases for known vulnerabilities matching enumerated software versions.
Manual ExploitationCraft and test payloads manually — understand exactly what the exploit does before running it. Modify public PoCs as needed.
Credential AttacksPassword spraying, credential stuffing with collected usernames. Brute-force only where explicitly in-scope and rate-limit safe.
Shell StabilisationUpgrade raw shells to fully interactive TTY. Python pty, socat, or rlwrap — never work in a raw netcat shell.

Tools

MetasploitNetcatExploitDB CrackMapExecHydrapwncat
05

Privilege Escalation

LINUX · WINDOWS · ACTIVE DIRECTORY

Once inside, I escalate to root or SYSTEM. I always enumerate manually first, then use automated scripts to catch anything I may have missed. Understanding why a privesc works matters more than just running a script.

Linux PrivEscSUID/SGID binaries, sudo -l misconfigurations, writable cron jobs, PATH hijacking, kernel exploits, and weak file permissions.
Windows PrivEscToken impersonation (PrintSpoofer, GodPotato), unquoted service paths, AlwaysInstallElevated, weak registry permissions.
Active Directory AttacksKerberoasting, AS-REP roasting, Pass-the-Hash, Pass-the-Ticket, DCSync, and ACL abuse paths found via BloodHound.

Tools

06

Post-Exploitation

PERSISTENCE · LATERAL MOVEMENT · EXFILTRATION

After reaching the objective, I document what an attacker could do — without actually causing harm. The goal is to demonstrate real business impact to drive accurate severity ratings and fix prioritisation.

Lateral MovementUse compromised credentials and tokens to pivot to adjacent hosts — pass-the-hash, SSH key reuse, and WMI/RDP.
Data Access AssessmentIdentify what sensitive data is accessible — PII, credentials, financial records — document without mass exfiltration.
Objective DocumentationCapture screenshots and request logs at each stage. Every step is traceable and reproducible for the report.
07

Reporting

FINDINGS · IMPACT · REMEDIATION

A pentest is only as valuable as its report. I write findings so a developer, a manager, and a CISO can all understand them. Every finding includes a reproduction path, impact statement, and concrete fix.

CVSS Severity RatingRate each finding with CVSS v3.1 — attack vector, complexity, privileges required, user interaction, and impact scope.
Finding StructureTitle → Severity → Summary → Steps to Reproduce → PoC → Impact → Remediation → References.
Remediation GuidanceSpecific, actionable fixes — not just "patch the server" but exact config changes, code patterns, or mitigating controls.
