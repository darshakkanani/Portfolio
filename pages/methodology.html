My Testing Methodology

A battle-tested, hunter-grade playbook refined through real bug bounty programs — from zero knowledge to critical finding.

Back to Resources
Hunter's Philosophy

Scanners find the obvious. Hunters find the rest. Every step in this methodology is manual-first — tools assist, they never lead. Think like an attacker, report like an engineer.

01

Passive Reconnaissance

OSINT · NO TRAFFIC TO TARGET · FOOTPRINTING

Before a single packet reaches the target, I build a complete intelligence picture. Passive recon is the most underrated phase — it surfaces hidden assets, legacy endpoints, and leaked secrets that active scanning will never find.

The goal: know more about the target than their own team does.

Pro Tip Certificate transparency logs expose subdomains even when DNS is locked down. Always start with crt.sh before touching any active tool.
Subdomain Enumeration (Passive) Query crt.sh, Censys, SecurityTrails, and VirusTotal for all known subdomains. Grep cert SANs for wildcard scopes. Feed into a deduplicated master list.
Google Dorks Hunt for exposed login panels, config files, directory listings, API keys, and error pages using targeted dorks: site:target.com ext:env, site:target.com inurl:api, site:target.com "internal use only".
GitHub & Source Code Leaks Search GitHub, GitLab, and Bitbucket for the org name, domain, and product names. Look for hardcoded API keys, DB credentials, internal endpoints, and commented-out debug code using github.com/search and TruffleHog.
Shodan / Censys / FOFA Search the target's IP ranges and ASN for exposed services, self-signed certs, default banners, and misconfigured cloud storage. Look for S3 buckets, GCP/Azure blobs, and Elasticsearch instances.
Employee & Org OSINT LinkedIn for employee names, roles, and tech stack mentions. HaveIBeenPwned and DeHashed for leaked credentials. Glassdoor/job postings often reveal internal tools, frameworks, and cloud providers.
Wayback Machine & Historical Data Pull archived URLs from web.archive.org and Common Crawl via waybackurls and gau. Old endpoints often still work and are forgotten by the team — goldmine for IDOR and legacy API keys.

Tools

subfinder amass crt.sh Shodan Censys theHarvester TruffleHog waybackurls gau Google Dorks
02

Active Enumeration

PORTS · DNS BRUTE · DIRECTORIES · PARAMETERS

Now I send traffic to the target — carefully and within scope. The aim is to resolve which subdomains are live, what ports are open, what paths exist, and what parameters the app accepts. Every discovery feeds the next step.

Pro Tip Run httpx over all enumerated subdomains to get status codes, titles, and tech headers in one pass before deep-diving anything individually.
DNS Brute-Force Run dnsx + subfinder + puredns with SecLists DNS wordlists to resolve all subdomains. Catch wildcard resolvers. Permute discovered subdomains with gotator to catch dev-api, staging-app, internal-admin patterns.
Port & Service Scanning Nmap full-port TCP scan (-p- -sV --open) on all in-scope IPs. Flag non-standard HTTP(S) ports, admin panels, Jenkins, Jira, Grafana, Redis, Elasticsearch, Docker APIs — all goldmines.
Directory & File Fuzzing FFUF with raft-medium-directories and raft-medium-files. Target: backup files (.bak, .old, ~), config files (.env, config.json, web.config), admin panels (/admin, /dashboard, /manage), and API docs (/swagger, /api-docs, /graphql).
Parameter Discovery Arjun on every endpoint to find hidden GET/POST parameters. Combine with param-miner (Burp extension) during manual browse. Unknown parameters = untested attack surface.
Technology Fingerprinting Wappalyzer, WhatWeb, and manual header analysis to map the full tech stack. Framework version → known CVEs. CDN detection for potential cache poisoning vectors.

Tools

Nmap FFUF dnsx puredns gotator httpx Arjun SecLists Wappalyzer Param Miner
03

Attack Surface Mapping

BURP · PROXY · JS ANALYSIS · MULTI-ROLE BROWSE

Every feature is proxied through Burp Suite and walked manually — as a guest, standard user, and privileged user. Every request, parameter, header, and cookie is catalogued. I treat this phase as building a complete map before attacking anything.

Most high-severity bugs come from features that aren't obviously interesting. Walk everything.

Pro Tip Create two accounts at every privilege level and keep them in separate browsers. Swap requests between accounts to instantly spot access control failures.
Full Manual Browse + Proxy Walk every user flow — onboarding, account settings, payments, file uploads, search, profile, admin. Capture all requests in Burp Site Map. Note: interesting parameters, numeric/predictable IDs, JWT tokens, and custom headers.
JavaScript Source Analysis Deobfuscate and beautify all JS bundles. Use LinkFinder and relative-url-extractor to pull hidden endpoints, API routes, internal paths, hardcoded keys, and feature-flagged functionality not visible in the UI.
API Schema Discovery For REST: probe /swagger.json, /openapi.yaml, /api/v1–v5, versioned paths. For GraphQL: run introspection query, map all types/mutations/queries with GraphQL Voyager. Look for deprecated mutations and hidden admin resolvers.
Multi-Role & Multi-Tenant Testing Map every role's permission surface. Identify all object IDs (user IDs, org IDs, resource IDs) per role. Note which endpoints enforce authorization server-side vs client-side only.
Cookie & Token Inventory Document every cookie (flags: Secure, HttpOnly, SameSite), JWT structure and algorithm, OAuth tokens, CSRF tokens. Flag anything base64-encoded or predictable for further testing.

Tools

Burp Suite Pro LinkFinder JS-Beautifier GraphQL Voyager Postman Param Miner Retire.js
04

Authentication & Session Testing

JWT · OAUTH · MFA BYPASS · SESSION MGMT

Auth bugs are disproportionately high-impact. A broken login or session issue can directly lead to account takeover — one of the most valuable findings in a bug bounty program.

I test every auth flow methodically, checking not just "does it work" but "what happens when it breaks in unexpected ways."

JWT Attacks Test alg:none (remove signature), algorithm confusion (RS256 → HS256 with public key as secret), weak secret brute-force with hashcat/jwt_tool, kid header injection (SQL/path traversal in kid param), jku/x5u header spoofing to serve attacker-controlled JWKS.
OAuth 2.0 Misconfigurations Test redirect_uri validation (open redirect → token theft), state parameter absence (CSRF on auth), code reuse / lack of PKCE, implicit flow token leakage in Referer header, and scope escalation.
Password Reset Flow Test token predictability (PRNG-based or timestamp-derived), token reuse after password change, host header injection in reset email link, username enumeration via timing/response differences, and password reset poisoning.
MFA Bypass Test: skipping MFA step entirely by going directly to post-auth URL, reusing OTPs, response manipulation (change "mfa_required":true to false), brute-forcing 6-digit TOTP with no rate limiting, and backup code exhaustion.
Session Management Session token entropy analysis. Test: session not invalidated after logout/password change, session fixation, concurrent session limits, cookie scope (domain/path), and session token in URL (Referer leakage).
Brute-Force & Rate Limiting Test missing rate limiting on login, OTP, and password reset endpoints. Check for lockout bypass via IP rotation headers (X-Forwarded-For, X-Real-IP, CF-Connecting-IP).

Tools

jwt_tool hashcat Burp Intruder Turbo Intruder Autorize OWASP ZAP
05

Injection Attacks

SQLi · XSS · SSTI · XXE · COMMAND INJECTION · LDAP

Every input that reaches a parser, interpreter, or database is a potential injection point. I test manually with hand-crafted payloads first — this catches context-specific bypasses that automated tools miss entirely.

Pro Tip Error messages are your best friend. A verbose SQL error, a Jinja2 trace, or an XML parse exception tells you exactly which engine you're injecting into.
SQL Injection Test all input parameters, headers (User-Agent, Referer, X-Forwarded-For), and cookies. Payloads: ', ", 1=1, time-based blind (SLEEP(5)), error-based, Union-based, OOB via DNS. Use SQLMap only after manual confirmation.
Cross-Site Scripting (XSS) Reflected, stored, and DOM-based. Test all input contexts: HTML body, HTML attribute, JS string, JS template literal, URL, CSS. Bypass filters with encoding, polyglots, tag breaking, and event handler variations. Escalate stored XSS to session theft, CSRF bypass, or keylogging PoC.
Server-Side Template Injection (SSTI) Probe with {{7*7}}, ${7*7}, #{7*7}, *{7*7} across all user-controlled inputs that appear in rendered output. Identify the template engine from error or output, then escalate to RCE with engine-specific payloads (Jinja2, Twig, Freemarker, Smarty).
XML External Entity (XXE) Test all XML upload/parsing endpoints. Payloads: classic file read (/etc/passwd), blind OOB via DNS callback, SSRF via http:// entity, and parameter entities for deeper bypass. Check for SVG, DOCX, and XLSX uploads which parse XML internally.
Command & Code Injection Any input that feeds system commands, shell scripts, or eval-like functions: test with ; id, | whoami, `id`, $(id), %0a id. Common targets: ping utilities, DNS lookup tools, file conversion services, and report generation features.
NoSQL & LDAP Injection MongoDB: {"$gt":""}, {"$where":"sleep(1000)"}. LDAP: *)(uid=*))(|(uid=*. Test login endpoints with operator injection to bypass authentication entirely.

06

Access Control & IDOR

HORIZONTAL · VERTICAL · MULTI-TENANT · FORCED BROWSING

Broken access control is consistently the #1 vulnerability class in bug bounty programs. IDOR alone accounts for a huge portion of critical/high findings. I test every object reference, every role boundary, and every assumed restriction.

Pro Tip The Autorize Burp extension automatically replays every request with a lower-privilege session — it catches horizontal IDOR at scale while you browse normally.
IDOR — Horizontal Escalation Replace numeric IDs, UUIDs, hashed values, and usernames across all endpoints — GET, POST, PUT, DELETE, PATCH. Test URL params, request bodies, JSON fields, and HTTP headers. A UUID doesn't mean it's not vulnerable.
Vertical Privilege Escalation Access admin endpoints with a standard user token. Test role/permission parameters in request bodies ("role":"admin"). Mass assignment — send extra fields the API accepts but the UI doesn't show. Modify JWT role claims.
Multi-Tenant Isolation In SaaS apps: test cross-tenant data access by using org/tenant IDs from one account in another's session. Check if resource IDs are globally sequential vs tenant-scoped. Target: documents, users, billing, and settings endpoints.
Forced Browsing & Function-Level Auth Directly access admin URLs, internal API endpoints, and debug routes. Test API versioning — /api/v2/admin may lack the auth checks added to v3. Access restricted features by guessing URL patterns from JS source.
HTTP Method Tampering Change GET→POST→PUT→DELETE→PATCH on every endpoint. Some servers apply auth middleware only to specific methods. Use X-HTTP-Method-Override header to tunnel methods through WAF-friendly verbs.

07

SSRF, CSRF & Open Redirects

OUT-OF-BAND · CLOUD METADATA · FILTER BYPASS

SSRF can turn a low-severity URL parameter into a critical cloud metadata takeover. CSRF turns a missing token into account compromise. Open redirects chain into phishing and OAuth token theft. These bugs punch above their weight.

SSRF — Blind & OOB Test all URL/URI parameters with an interactsh/Burp Collaborator callback. Bypass filters: IP encoding (0x7f000001, 2130706433, 0177.0.0.01), DNS rebinding, http://localhost, IPv6 (::1). If AWS: target 169.254.169.254/latest/meta-data for IMDSv1 credentials.
SSRF — Protocol Smuggling Test non-HTTP schemes: file:///etc/passwd, dict://, gopher://, ftp://. Gopher can be used to forge arbitrary TCP payloads — SMTP, Redis, Memcached, internal APIs.
CSRF Check every state-changing request (POST/PUT/DELETE) for CSRF token. Test: token absence, token reuse, token tied to session vs global, SameSite=None without Secure, JSON body CSRF (change Content-Type to text/plain). Build a minimal PoC HTML page to confirm exploitability.
Open Redirect Test all redirect, return, next, url, goto, destination parameters. Bypass filters: //attacker.com, ////attacker.com, https://trusted.com@attacker.com, URL encoding, backslash-based. Chain with OAuth for token theft.

08

Business Logic Testing

RACE CONDITIONS · PRICE MANIPULATION · WORKFLOW BYPASS

Business logic bugs cannot be found by any scanner. They require understanding the application's intended workflow — and then systematically testing every assumption it makes. These are often the highest-impact, most creative findings.

Pro Tip Think about what the developer assumed would never happen. Negative quantities, zero-price checkouts, applying a coupon after payment, completing step 3 before step 2 — if it wasn't explicitly prevented, test it.
Race Conditions Use Turbo Intruder or Burp's Last-Byte Sync to send parallel requests. Target: coupon single-use bypass, free-credit double-spend, vote/like counting, gift card redemption, referral bonus abuse, and concurrent withdrawal.
Price & Quantity Manipulation Modify price, quantity, discount, and total fields in requests. Test: negative quantities, zero/negative prices, integer overflow on large quantities, and applying discounts to items that should be excluded.
Workflow & State Machine Bypass Skip steps in multi-stage flows: jump from step 1 to step 3, access post-payment pages pre-payment, reuse one-time confirmation tokens, bypass email verification, complete actions in reverse order.
Coupon & Referral Abuse Stack multiple coupons, apply expired codes, reuse single-use codes after order cancellation, self-referral loops, and referral bonus without completing required action.
File Upload Abuse Test: unrestricted file types (PHP/JSP webshell upload), MIME type bypass, double extension (file.php.jpg), null byte (file.php%00.jpg), path traversal in filename, zip slip (archive containing ../../evil), SVG XSS via image upload, and storing files in web-accessible directories.

09

API & JavaScript Deep Dive

REST · GRAPHQL · MOBILE APIs · EXPOSED SECRETS

Modern apps live and die by their APIs. Frontend JS bundles contain the full map of what the app can do — including things the UI deliberately hides. This phase extracts everything that wasn't meant to be found.

GraphQL Exploitation Enable introspection if disabled via field suggestion. Test: introspection → dump all types → find admin mutations → test unauthenticated access → batch query abuse (sending 1000 queries in one request to bypass rate limits) → field-level auth gaps.
REST API Security Test API versioning gaps (v1 vs v2 auth enforcement), mass assignment (send extra fields), HTTP verb tampering, BOLA/IDOR on resource IDs, missing authentication on bulk/export endpoints, and improper error handling leaking stack traces.
JS Secret Hunting Grep all JS files for: API keys, AWS access keys, Stripe/Twilio keys, Firebase configs, internal service URLs, hardcoded credentials, and feature flags. Use truffleHog and secretfinder. Check source maps (.js.map) for original unminified source.
Mobile API Analysis Intercept mobile app traffic via Burp + Android emulator or iOS with SSL kill switch. Mobile APIs often have weaker auth, missing rate limits, and additional admin endpoints not exposed in the web app. Decompile APK with jadx to extract hardcoded keys and hidden endpoints.

10

Exploitation & Vulnerability Chaining

IMPACT MAXIMISATION · PoC · CHAIN BUILDING

A P3 reflected XSS combined with a CSRF bypass and a weak CORS policy becomes a P1 account takeover. The best hunters don't just find bugs — they chain them into the maximum demonstrable impact.

I build the smallest, most reliable PoC that proves the real-world damage. No destructive actions — I stop at proof and document every step.

Pro Tip Always ask: "if I were a real attacker, what would I do next with this?" That second step is often the finding that turns a medium into a critical.
Classic Chain: Stored XSS → ATO Inject a stored XSS payload that steals the victim's session cookie or sends a state-changing request (email/password change) on their behalf, silently escalating to full account takeover.
Classic Chain: SSRF → Cloud Credentials SSRF to 169.254.169.254 → read IMDSv1 IAM role credentials → use credentials to access S3 buckets, Lambda functions, RDS snapshots, or escalate to full AWS account access.
Classic Chain: Open Redirect → OAuth Token Theft Craft OAuth auth request with redirect_uri pointing to an open redirect on the trusted domain. Victim authenticates, token lands in attacker's server logs via Referer header.
Screenshot & Evidence Collection For every confirmed finding: capture the full HTTP request/response pair from Burp, a browser screenshot proving impact, a screen recording for complex multi-step chains, and the exact reproduction steps as a numbered list.
CVSS v3.1 Impact Assessment Score each finding honestly: AV (Network/Adjacent/Local/Physical), AC (Low/High), PR, UI, S, C/I/A impact. Don't overstate — triage teams reject inflated severities and it hurts your reputation. Undersell impact in PoC, justify the score in writing.
11

Reporting

CVSS · CLEAR WRITE-UP · TRIAGE-READY · REMEDIATION

A vulnerability that can't be communicated clearly doesn't get fixed — and in bug bounty, it doesn't get paid. Every report I write follows a format that a developer who has never heard of the vulnerability can read, reproduce, and patch.

Quality over quantity. One clear, well-evidenced report beats five vague ones every time.

Report Structure Title (vuln type + affected endpoint) → Severity (CVSS score + justification) → Summary (2–3 sentences, plain English) → Steps to Reproduce (numbered, exact URLs and payloads) → PoC (Burp screenshot + raw request) → Impact (who is affected, what data/action is at risk) → Remediation → References.
Severity Scoring (CVSS v3.1) Use the official calculator. Rate AV, AC, PR, UI, Scope, and C/I/A impact. Include the vector string (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H). Justify non-obvious choices in the description.
Remediation Guidance Specific, not generic. Not "sanitise input" but "use parameterised queries with PDO / prepared statements." Not "validate redirects" but "maintain a server-side whitelist of allowed redirect destinations and reject anything not on it." Give the dev the fix, not just the problem.
Communication & Triage Collaboration Respond to triage questions within 24 hours. If marked as informative or N/A, ask for clarification with additional evidence — don't argue, educate. Build a track record of accurate, well-written reports for program priority.

Report template includes

Title Severity (CVSS v3.1) Summary Steps to Reproduce PoC (Request + Screenshot) Impact Remediation References (CWE / OWASP)
