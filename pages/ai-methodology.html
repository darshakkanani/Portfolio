01

Threat Modelling

ARCHITECTURE REVIEW · TRUST BOUNDARIES · ATTACK SURFACE

Before sending a single prompt I map the entire AI system — its components, data flows, trust boundaries, and integration points. Understanding the architecture determines every attack path that follows.

I align findings against OWASP LLM Top 10 and MITRE ATLAS from the start, so every phase maps to a documented risk class.

System Architecture MappingIdentify model provider, prompt pipeline, retrieval sources (RAG), tool integrations, output handlers, and user trust levels.
Trust Boundary AnalysisDefine what inputs the model accepts, which are user-controlled vs system-controlled, and where output is rendered or executed downstream.
OWASP LLM Top 10 MappingPre-map the application against all 10 LLM risk categories — prompt injection, insecure output handling, supply chain, excessive agency, and more.
System Prompt DiscoveryAttempt to surface the system prompt via leakage techniques, indirect prompting, and error message analysis — knowing instructions defines the attack surface.

02

Reconnaissance

MODEL FINGERPRINTING · API ENUMERATION · SUPPLY CHAIN

Identify the underlying model, version, provider, and any third-party plugins or tools the application exposes. Supply-chain weaknesses and outdated model versions often yield the most impactful findings.

Model FingerprintingUse knowledge-boundary probes, training-data artefacts, and distinctive response patterns to identify the underlying base model and version.
API & Endpoint EnumerationDiscover exposed inference endpoints, streaming endpoints, and function-calling schemas. Check for unauthenticated access and verbose error messages.
Plugin & Tool InventoryEnumerate all tools, plugins, and external integrations the model can call — each integration is a potential pivot point for privilege escalation or data exfiltration.
RAG & Knowledge Base ReconIf the application uses retrieval-augmented generation, probe data sources for over-exposure, indirect injection vectors, and sensitive document leakage.

03

Prompt Injection

DIRECT · INDIRECT · JAILBREAKS · ROLE MANIPULATION

Prompt injection is the primary attack class for LLM applications. I test both direct injection (user input overrides instructions) and indirect injection (malicious content ingested from external sources), as well as alignment-bypass jailbreaks.

Direct Prompt InjectionInject instructions into user-controlled fields to override system prompts, exfiltrate instructions, and alter model behaviour — "Ignore previous instructions and…" variants.
Indirect Prompt InjectionEmbed malicious instructions in documents, web pages, emails, or database entries that the model retrieves and processes — the model acts on attacker-controlled content without user awareness.
Jailbreaks & Alignment BypassesRole-play framing, hypothetical scenarios, DAN-style prompts, token smuggling, and language-switching to bypass safety filters and content policies.
System Prompt ExfiltrationExtract confidential system instructions via indirect leakage, token-by-token completion, and translation / encoding tricks.

04

Model-Level Attacks

DATA EXTRACTION · INVERSION · MEMBERSHIP INFERENCE

Beyond prompt manipulation, I probe for attacks that target the model itself — extracting training data, inferring membership of sensitive records, and assessing insecure output handling that can lead to code execution or SSRF downstream.

Training Data ExtractionUse repeated, targeted completions and memorisation probes to surface verbatim training data — PII, API keys, or proprietary content inadvertently memorised.
Membership InferenceDetermine whether specific records (user data, documents) were included in fine-tuning datasets — relevant for privacy compliance and data breach assessment.
Insecure Output HandlingTest whether model-generated content (markdown, HTML, code, shell commands) is rendered or executed unsanitised downstream — leading to XSS, SSRF, RCE, or SQL injection.
Hallucination & OverrelianceAssess how confidently the model fabricates facts, citations, or code — and whether the application blindly trusts and acts on those outputs without validation.

05

Application-Layer Testing

EXCESSIVE AGENCY · AUTHZ · RATE LIMITING · SUPPLY CHAIN

The surrounding application is as important as the model itself. I test every integration point — tool calls, agentic actions, API access controls, rate limits, and third-party model or plugin supply chains.

Excessive Agency TestingVerify the model's granted permissions are least-privilege — test whether tool calls can be abused to read/write files, send emails, execute code, or access unauthorised resources.
Authorisation & Multi-TenancyIn multi-user deployments, test whether conversation context, memory, or tool outputs can be accessed across user sessions or tenant boundaries.
Rate Limiting & DoSCheck for missing rate limits on inference endpoints — automated prompt flooding can exhaust quotas, degrade service, or inflate costs for the operator.
Supply Chain & Plugin RiskEvaluate third-party model providers, fine-tuning pipelines, and plugins for backdoors, data exfiltration risks, and insecure dependencies (LLM10: Model Theft).

06

Reporting & Disclosure

FINDINGS · IMPACT · REMEDIATION · RESPONSIBLE DISCLOSURE

AI security findings require extra care in communication — the non-deterministic nature of LLMs means reproduction steps must include exact prompts, model versions, and temperature settings. I follow coordinated responsible disclosure for all AI findings.

Severity RatingMap each finding to OWASP LLM Top 10 and CVSS v3.1 — account for non-determinism, model version specificity, and real-world exploitability in the rating.
Finding StructureTitle → Severity → OWASP LLM Category → Summary → Exact Prompt / Steps to Reproduce → PoC Output → Impact → Remediation → References.
Remediation GuidanceConcrete mitigations — input/output validation, prompt hardening, principle of least privilege for tool access, content filtering, and model versioning strategies.
Responsible DisclosureFollow coordinated disclosure timelines — notify the vendor privately, allow reasonable remediation time, and publish only after a fix is in place or the agreed embargo expires.
