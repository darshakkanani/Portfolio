My Testing Methodology

A personal, battle-tested approach to web application security testing — from initial recon to final report.

01

Reconnaissance

PASSIVE · OSINT · FOOTPRINTING

Before touching the target, I gather as much information as possible without sending a single packet to it. The goal is to build a complete picture of the target's infrastructure, technologies, and people.

Good recon saves hours during testing and often surfaces vulnerabilities that active scanning completely misses.

Domain & Subdomain Discovery Enumerate subdomains via certificate transparency logs (crt.sh), brute-force (dnsx, subfinder, amass), and Google dorks.
OSINT — People & Org LinkedIn employees, GitHub repos, leaked credentials via HaveIBeenPwned, Pastebin, and breach databases.
Technology Fingerprinting Identify tech stack via Wappalyzer, BuiltWith, HTTP headers, and response signatures.
Shodan / Censys / FOFA Surface exposed services, open ports, and misconfigured cloud assets attached to the target's IP ranges and ASN.

Tools

subfinder amass dnsx httpx crt.sh Shodan theHarvester Google Dorks
02

Enumeration

ACTIVE · PORTS · DIRECTORIES · PARAMETERS

With a target list in hand, I move to active enumeration — probing what services are running, what paths exist, and what parameters are accepted. I stay within scope at all times.

Port & Service Scanning Nmap full-port scans on all in-scope IPs. Identify non-standard HTTP ports, admin panels, and exposed services.
Directory & File Fuzzing FFUF and Gobuster with curated wordlists (SecLists) to discover hidden paths, backup files, and admin endpoints.
Parameter Discovery Arjun for hidden GET/POST parameters. Collect all JS endpoints from page source and bundled scripts.
Authentication Endpoints Map all login, register, password reset, OAuth flows, and API key endpoints for focused auth testing.

Tools

Nmap FFUF Gobuster Arjun httpx SecLists waybackurls
03

Attack Surface Mapping

BURP · PROXY · JS ANALYSIS · API MAPPING

I proxy all traffic through Burp Suite and manually walk through every feature of the application as different user roles — unauthenticated, standard user, privileged user. Every endpoint, parameter, and header is catalogued.

Manual Browse + Proxy Walk every user flow in Burp Suite — capture all requests, note interesting parameters, response differences, and error messages.
JavaScript Analysis Extract all API endpoints, tokens, and secrets from JS bundles using LinkFinder and manual review.
API Discovery Map REST and GraphQL APIs — enumerate schemas, mutations, queries, and unauthenticated endpoints.
Role Differentiation Test as each role to surface privilege escalation, IDOR, and access control issues from the start.

Tools

Burp Suite LinkFinder JS-Beautifier Postman GraphQL Voyager
04

Vulnerability Testing

OWASP · MANUAL · AUTOMATED

I test each attack class manually first, then layer automated scanning on top. Manual testing always comes first — scanners miss logic flaws, chained vulnerabilities, and anything that requires session context.

Injection (SQLi, XSS, SSTI, XXE) Manually craft payloads for each injection context. Use SQLMap only to confirm manually found SQLi, not as a discovery tool.
Authentication & Session Test brute-force protections, password reset flows, JWT alg:none / weak secrets, OAuth misconfigurations, session fixation.
IDOR & Access Control Replace IDs in every request — numeric, UUIDs, hashed. Test horizontal and vertical escalation across all roles.
SSRF, CSRF, Open Redirect Test all URL/redirect parameters and out-of-band callbacks (Burp Collaborator / interactsh) for SSRF. Test state-changing requests for missing CSRF tokens.
Business Logic Test price manipulation, coupon stacking, race conditions, negative quantities, state machine bypasses, and workflow skipping.

Tools

Burp Suite Pro SQLMap Nuclei jwt_tool interactsh Turbo Intruder
05

Exploitation

PROOF OF CONCEPT · IMPACT DEMONSTRATION

When a vulnerability is confirmed, I build a minimal, reliable proof of concept that demonstrates the real-world impact clearly. I never cause harm — I stop at the point of proof and document everything I did.

Minimal PoC Construction Build the smallest possible payload or request sequence that proves the vulnerability. No destructive actions.
Impact Chaining Look for combinations — can a stored XSS + CSRF chain to account takeover? Does SSRF reach internal metadata endpoints?
Screenshot & Request Capture Capture full HTTP request/response pairs, screenshots, and video recordings where needed.
06

Post-Exploitation

LATERAL MOVEMENT · PRIVILEGE ESCALATION · DATA ACCESS

Where in scope, I assess what an attacker could do with the access gained — what data is reachable, what other systems are accessible, and what the blast radius is. This drives accurate severity ratings.

Privilege Escalation Attempt to escalate from found access to admin or higher-privilege roles via further IDOR, JWT manipulation, or logic flaws.
Data Exposure Assessment Determine which sensitive records are accessible — PII, financial data, credentials — and document minimum necessary to prove the issue.
07

Reporting

CVSS · CLEAR WRITE-UP · REMEDIATION ADVICE

A vulnerability that can't be clearly communicated doesn't get fixed. I write every report so a developer who has never heard of the issue can understand it, reproduce it, and fix it.

CVSS Severity Scoring Rate each finding using CVSS v3.1 — Attack Vector, Complexity, Privileges Required, Impact — and justify the score.
Write-up Structure Title → Summary → Severity → Steps to Reproduce → PoC (screenshot / request) → Impact → Remediation.
Remediation Guidance Always include a concrete fix — not just "sanitise input" but specific library calls, config changes, or code patterns that address the root cause.
